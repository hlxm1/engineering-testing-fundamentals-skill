# 第8章：虚拟仪器及工程应用

**定位**：印刷p.216–234 / PDF第225–243页。概念p.216；硬件p.218；软件p.221；应用p.231。

## 核心问题
虚拟仪器用软件组织硬件资源、分析算法和人机界面；“软件即仪器”不意味着不需要真实传感器、采样和校准。面板能显示波形只是完整测量链的一部分。

## 框架一：硬件—软件—测量任务分层
1. 任务层明确被测量、量程、频带、精度、同步和输出需求。
2. 硬件层选择传感器、调理、采集与接口；原书讨论DAQ、GPIB、VXI等结构。
3. 软件层处理驱动调用、参数设置、数据管理、分析与显示。
4. 验证层提供已知输入、期望输出和端到端校验；不把模拟数据误标为实测。

前三项由原书硬件/软件思想整理；第4项及下述质量门是本技能为可复用实现增加的工程规则。

## 框架二：把可重用分析核心从界面剥离
原书讨论LabVIEW图形化编程与LabWindows/CVI的C语言、事件与回调式开发，并用波形、自相关、自谱界面演示。可迁移的原则是：
- 先定义采样数据契约：值、单位、fs、通道、量程、采样时刻及有效性。
- 数据生成/硬件读取、数值算法、界面显示分别组织。
- 启停采集由状态管理，不在每次重画时重新初始化硬件。
- 所有分析都使用同一版采样参数，不让界面改了fs而旧数据沿用新频轴。
- 原始数据与处理结果分开保存，注明去均值、加窗、滤波和归一化。

## 决策矩阵
| 情况 | 采用的策略 | 取舍 |
|---|---|---|
| 验证算法正确性 | 已知合成信号 + 独立预期值 | 不能替代硬件测试 |
| 接真实采集 | 适配器转换成固定数据契约 | 增加接口层但便于替换 |
| 用户连续调参 | 参数快照绑定数据批次 | 避免新参数解释旧数据 |
| 显示跟不上采样 | 采集与显示解耦，明确抽取 | 显示可降率，原始记录不可静默丢样 |
| 多设备同步 | 核实硬件时钟/触发和延迟 | 通信返回速度不等于同步精度 |
| 升级旧工程 | 先保留测量定义与测试基线 | 原书菜单和API不当现行语法 |

## 自编实施例：最小频谱虚拟仪器
### 数据与验收
输入合成波形 `x=2+3sin(2π·50t)`，fs=1000 Hz，N=2000；生成器是测试输入，不是假冒真实传感器。

### 分层步骤
1. **输入适配**：产生数值序列及单位、fs、N、信号来源标签。
2. **统计模块**：算均值2、总RMS约2.9155；去均值RMS约2.1213。
3. **谱模块**：定义单边幅值谱，验证50 Hz幅值约3、直流约2；注明归一化，DC与Nyquist不倍增。
4. **显示模块**：时轴、频轴和幅值轴都带单位，显示当前处理参数。
5. **记录模块**：保存原始序列、处理参数和校验结果。
6. **接硬件后**：用已知电输入替换生成器，再做物理量全链校准。

仓库教学程序用自编DFT实现小规模验证，不复制原书CVI界面或源码；DFT速度不代表生产级FFT性能。

## 失败模式
- 不注明单边/双边谱，使幅值出现2倍错误。
- 峰值、RMS、功率与功率谱密度混用同一单位标签。
- “运行无报错”替代数值基准测试。
- 图形刷新阻塞采集，把漏点补成直线后宣称连续记录。
- 用软件界面上的滑块设置值冒充硬件已经接受的实际参数。
